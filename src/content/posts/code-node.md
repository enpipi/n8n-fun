## Codeノードの利用シナリオ
n8nのCodeノードは、ワークフロー内でJavaScriptコードを実行できる強力なノードです。標準ノードでは実現できない複雑な処理や、独自のビジネスロジックを実装する際に重要な役割を果たします。主な利用シナリオとして、データ変換・操作、カスタムロジックの実行、実行モードの選択、そしてセキュリティ制限の理解が挙げられます。
### データ変換と操作
Codeノードの最も一般的な用途は、入力データの変換と操作です。JSONデータの構造変更、文字列の加工、数値計算、配列操作など、様々なデータ処理を柔軟に行えます。例えば、APIから取得したデータを別のシステムで使用可能な形式に変換したり、複数のデータソースを結合して新しいデータ構造を作成することが可能です。
具体的には、日付フォーマットの変更、テキストの正規化、条件に基づくデータフィルタリング、統計計算などが頻繁に実行されます。標準のSet NodeやFunction Nodeでは対応が困難な複雑なデータ操作も、JavaScriptの豊富な機能を活用することで効率的に処理できます。
### カスタムロジックの実行
ビジネス固有の処理ロジックや、標準ノードでは実現できない特殊な処理をCodeノードで実装できます。複雑な条件分岐、独自のアルゴリズム、外部ライブラリの活用など、JavaScriptの全機能を利用した高度な処理が可能です。
例えば、独自の暗号化・復号化処理、特殊な文字エンコーディング変換、機械学習モデルの推論処理、カスタムバリデーション、複雑な在庫管理ロジックなどを実装できます。また、try-catch文を使用したエラーハンドリングも組み込むことで、堅牢なワークフローを構築できます。
### 実行モードの選択（Run Once for All Items / Run Once for Each Item）
Codeノードでは、データ処理方法を「Run Once for All Items」と「Run Once for Each Item」の2つのモードから選択できます。この選択は処理効率とロジックの複雑さに大きく影響するため、適切なモード選択が重要です。
「Run Once for All Items」モードでは、すべての入力アイテムを一度にまとめて処理します。このモードは、アイテム間の比較や集計処理、バッチ処理に適しています。例えば、売上データの合計計算、重複データの除去、ソート処理などで効果的です。コード内では`$input.all()`を使用してすべてのアイテムにアクセスできます。
一方、「Run Once for Each Item」モードでは、各アイテムに対して個別にコードを実行します。このモードは、アイテム固有の変換処理や、各アイテムに対する独立した処理に適しています。例えば、各レコードの値を個別に変換したり、条件に基づいて各アイテムを異なる方法で処理する場合に使用します。コード内では`$input.item`で現在のアイテムにアクセスできます。
### ファイルシステムとHTTPリクエストの制限
セキュリティ上の理由から、Codeノードにはいくつかの重要な制限が設けられています。これらの制限を理解することで、安全で効果的なワークフローを設計できます。
ファイルシステムへのアクセスは制限されており、`fs`モジュールや`require()`を使用したローカルファイルの読み書きは許可されていません。これにより、機密ファイルへの不正アクセスやシステムファイルの破損を防いでいます。ファイル操作が必要な場合は、専用のファイル操作ノードや外部ストレージサービスのAPIを使用することが推奨されます。
同様に、直接的なHTTPリクエストの実行も制限されています。`fetch()`や`XMLHttpRequest`などを使用した外部APIへのリクエストは実行できません。外部サービスとの通信が必要な場合は、HTTP RequestノードやWebhookノード、各種サービス専用ノードを使用する必要があります。これらの制限により、予期しないネットワーク通信やデータリークを防ぎ、ワークフローの安全性を確保しています。
これらの制限は、n8nの実行環境を保護し、セキュアな自動化プラットフォームを提供するための重要な設計方針です。制限を理解した上で、適切なノードの組み合わせにより、安全で効率的なワークフローを構築することが可能です。
## JavaScriptでの使用方法
n8nのCode Nodeでは、JavaScriptを使用してワークフロー内でカスタムロジックを実行できます。Code NodeはNode.js環境で動作し、ES6+の機能を含む現代的なJavaScript構文を完全にサポートしています。基本的な使用方法として、入力データの変換、計算処理、条件分岐など、標準的なJavaScript機能をすべて利用することができます。
### Promiseとデバッグ機能
Code NodeではPromiseとasync/await構文を完全にサポートしており、非同期処理を簡単に実装できます。`await`キーワードを使用して外部APIの呼び出しや時間のかかる処理を待機することが可能です。デバッグ機能として、`console.log()`を使用してデバッグ情報をワークフロー実行ログに出力できます。また、エラーハンドリングのためのtry-catch構文も利用でき、例外が発生した場合は適切なエラーメッセージと共にワークフローの実行が停止されます。
### 外部ライブラリの利用（セルフホスト版とCloud版の違い）
外部ライブラリの利用方法は、セルフホスト版とCloud版で大きく異なります。セルフホスト版では、Node.jsの`require()`関数を使用してサーバーにインストールされた任意のnpmパッケージを利用できます。事前にDockerコンテナまたはサーバー環境にライブラリをインストールする必要がありますが、柔軟性が高く、専門的なライブラリも利用可能です。
一方、Cloud版では、セキュリティ上の理由から外部ライブラリの使用が制限されており、n8nが事前に提供する承認されたライブラリのみ利用できます。ただし、lodash、moment、axios等の人気ライブラリは利用可能で、一般的な用途には十分対応できます。Cloud版を使用する場合は、利用可能なライブラリのリストを事前に確認することが重要です。
### 組み込みメソッドと変数
Code Nodeには、n8n特有の組み込みメソッドと変数が用意されています。最も重要なのは`$input`変数で、これを使用して前のノードからの入力データにアクセスできます。`$input.all()`で全ての入力アイテムを取得し、`$input.first()`で最初のアイテムのみを取得できます。
その他の重要な組み込み変数として、`$node`（現在のノード情報）、`$workflow`（ワークフロー情報）、`$execution`（実行情報）があります。また、`$jmespath()`メソッドを使用してJSONデータの複雑なクエリを実行したり、`$now`で現在時刻を取得したりすることも可能です。これらの組み込み機能を活用することで、より効率的なデータ処理が実現できます。
### キーボードショートカット
Code Nodeのエディターでは、開発効率を向上させるための様々なキーボードショートカットが利用できます。`Ctrl+S`（Mac: `Cmd+S`）でコードを保存し、`Ctrl+Enter`（Mac: `Cmd+Enter`）でコードを実行できます。`Ctrl+/`（Mac: `Cmd+/`）で選択した行をコメントアウトし、`Ctrl+Z`（Mac: `Cmd+Z`）で元に戻すことができます。
エディター内でのナビゲーションには、`Ctrl+G`（Mac: `Cmd+G`）で指定した行にジャンプし、`Ctrl+F`（Mac: `Cmd+F`）で検索機能を使用できます。また、`Tab`キーでインデントを追加し、`Shift+Tab`で削除できるなど、一般的なコードエディターと同様のショートカットが使用できるため、既存の開発経験を活かすことができます。
## Pythonでの使用方法
n8nのCode NodeではPythonコードを実行することができ、現在2つのPython実行環境が提供されています。従来のPyodide（レガシー機能）と新しいNative Python（ベータ機能）の両方をサポートしており、ワークフローの要件に応じて選択できます。
### Pyodide（レガシー機能）
PyodideはWebAssembly上で動作するPython環境で、n8nの初期のPython実装として使用されてきました。ブラウザ環境でPythonコードを実行できる利点がありますが、いくつかの制限があります。
Pyodideの主な特徴：
- WebAssembly上で動作するため、ブラウザ環境での実行が可能
- NumPy、Pandas、Matplotlib等の科学計算ライブラリが利用可能
- ファイルシステムへのアクセスに制限がある
- ネイティブPythonと比較して実行速度が劣る場合がある
Code NodeでPyodideを使用する場合、言語選択で「Python (Pyodide)」を選択します。基本的なPython構文はそのまま使用でき、n8nの入力データは `items` 変数を通じてアクセスできます。
### Native Python（ベータ機能）
Native Pythonは新しく導入されたベータ機能で、本格的なPython環境での実行を提供します。Pyodideの制限を克服し、より高速で柔軟な実行環境を実現しています。
Native Pythonの主な利点：
- ネイティブPython環境での高速実行
- 豊富なPythonパッケージエコシステムへのフルアクセス
- ファイルシステム操作の完全サポート
- 外部APIやデータベースへの直接接続が可能
ベータ機能として提供されているため、本番環境での使用時は注意が必要です。しかし、将来的にはn8nのメインPython実行環境として推奨される予定です。
Native Pythonを使用する場合、n8nのセルフホスト環境でPython実行環境を適切に構成する必要があります。クラウド版では段階的に展開されており、利用可能性を確認してからの使用を推奨します。
### PythonとJavaScriptの違い
n8nのCode NodeにおけるPythonとJavaScriptの実装には、いくつかの重要な違いがあります。これらの違いを理解することで、適切な言語選択と効果的なコード記述が可能になります。
**データアクセス方法の違い：**
JavaScriptでは `$input.all()` や `$input.item` などのn8n固有の関数を使用してデータにアクセスしますが、Pythonでは `items` 変数を通じて直接データにアクセスします。この違いにより、Pythonの方がより直感的なデータ操作が可能です。
**ライブラリエコシステム：**
JavaScriptはNode.jsのnpmエコシステムにアクセスできますが、Pythonは科学計算、データ分析、機械学習に特化した豊富なライブラリ（NumPy、Pandas、Scikit-learn等）を利用できます。データ処理や分析タスクにはPythonが有利です。
**パフォーマンス特性：**
JavaScriptはV8エンジンの最適化により高速実行が可能で、非同期処理に優れています。一方、PythonのNative実行環境では、特にNumPyやPandasを使用したベクトル化演算で高いパフォーマンスを発揮します。
**エラーハンドリングと debugging：**
JavaScriptではPromiseベースの非同期エラーハンドリングが必要ですが、Pythonでは従来のtry-except構文を使用できます。また、Pythonの方がより詳細なスタックトレースとエラー情報を提供する場合が多いです。
適切な言語選択の指針として、Web API統合や非同期処理が中心の場合はJavaScript、データ分析や科学計算が必要な場合はPythonを選択することを推奨します。
## その他の機能と参考資料
Code Nodeは基本的なコード実行機能に加えて、開発者の生産性を向上させる様々な支援機能を提供しています。また、豊富なサンプル事例とテンプレートが用意されており、初心者から上級者まで幅広いユーザーが効率的にワークフローを構築できるよう設計されています。
### AIによる支援機能
n8nのCode NodeにはAIアシスタント機能が統合されており、コード作成を強力にサポートします。この機能により、自然言語での指示からJavaScriptやPythonコードを自動生成できるため、プログラミング経験が限られたユーザーでも複雑なデータ処理ロジックを実装することが可能です。
AIアシスタントは、データ変換、API応答の解析、条件分岐の作成など、一般的なワークフローパターンを理解しており、文脈に応じた適切なコード例を提案します。また、既存のコードに対してもリファクタリングや最適化の提案を行い、コード品質の向上をサポートします。エラーが発生した場合には、エラーメッセージを分析して修正案を提示する機能も備えています。
### サンプル事例とテンプレート
n8nコミュニティとドキュメントサイトでは、Code Nodeを活用した実践的なサンプル事例が豊富に提供されています。これらのテンプレートには、データクリーニング、APIデータの変換、条件付きロジックの実装、外部システムとの連携など、実際のビジネスシーンで頻繁に使用されるパターンが含まれています。
特に人気の高いテンプレートには、CSV/JSONデータの変換処理、Webhook応答の加工、配列データの操作、日付・時刻の計算、文字列処理のパターンなどがあります。各テンプレートには詳細なコメントと使用方法が記載されており、そのまま利用することも、カスタマイズのベースとして活用することも可能です。また、コミュニティが作成したテンプレートは定期的に更新され、新しいユースケースや改善されたコードパターンが継続的に追加されています。
これらのリソースを活用することで、開発時間を大幅に短縮し、ベストプラクティスに従った信頼性の高いワークフローを構築することができます。初心者はテンプレートから学習を開始し、経験を積むにつれて独自のロジックを開発していくという段階的なアプローチが推奨されています。
